# DRAFT: step time per config (not blog prose; for review)

Generated by `kimi_k3_step_time.py` (practical roofline + communication +
overlap penalty + PP schedule), configs that fit in 192 GB only. Rerun:
`PYTHONPATH=. python <rank script>` (see the session notes).

Assumptions to review:
- **FSDP across NVLink domains (no PP):** two columns. *Hierarchical*: each GPU's
  NIC carries only the other domains' shards ((D-1)/N of the tensor), the rest
  over NVLink. *Naive ring*: every byte through each GPU's own NIC at 50 GB/s.
  Being measured on the GB300 cluster (2 and 4 hosts over InfiniBand).
- **Overlap penalty:** compute 1.29x and collectives 1.6x while overlapped
  (4-GPU NVLink measurement, NCCL default 32 channels).
- **PP hops:** InfiniBand at 50 GB/s per GPU; sender / receiver penalty from
  the NVLink one-way measurement (1.24x / 1.31x), pending the InfiniBand one.
- **PP transports:** *chain* = TorchTitan's 1F1B today (hidden + whole block
  stack every hop); *direct* = each block straight to its consumers, only the
  hidden state on the critical path (penalties still charged); *cache* =
  TorchTitan's interleaved transport (only blocks the receiving rank has not seen).
- **Direct distribution's extra memory** (not in the memory model): each
  producer keeps a gradient-accumulation buffer per in-flight microbatch for its
  block (stage 0 of PP 8, TP 2, 8K: 8 x 59 MB = 0.5 GB), and later stages buffer
  blocks that arrive early (stage 7: up to 28 x 59 MB = 1.6 GB, but stage 7 holds
  far fewer microbatches than stage 0). Neither moves the peak.
- **Bubble:** (M + (P - 1) / v) / M, with the period of the slowest rank.
- CP communication assumed hidden but charged its penalty; EP inside DistMoE.
- The optimizer step is not included.
