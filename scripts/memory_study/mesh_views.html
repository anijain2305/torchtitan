One set of GPUs, several device meshes

A device mesh is a labeling of the same ranks, not a separate set of GPUs. torchtitan builds several meshes by reshaping the flat rank list row-major (parallelism_context.py): a dense view (dp_shard, cp, tp) and a sparse (expert) view (edp_shard, ep). Each axis is a set of process groups, so a TP pair, an EP group and an FSDP group are all sets of the same GPUs. Hover any rank to see every group it belongs to.

Shown on 32 GPUs so every rank fits; the post's layout (512 GPUs, dp_shard 256 × tp 2, EP 64, so edp_shard 8) has the same structure with longer rows.

What each group does

  • TP group (dense view, axis tp): activation all-gather / reduce-scatter around attention and the shared-expert MLP; splits TP-sharded weights.
  • CP group (axis cp): K/V exchange (MLA, Ulysses all-to-all) and KDA state passing; tokens split for the whole layer.
  • Data-parallel group (axis dp_shard): ranks that get different microbatches; the TP and CP ranks inside a data-parallel rank share one microbatch.
  • Dense FSDP group (dp_shard and cp): all-gather / reduce-scatter of dense weights and gradients. CP folds in because CP ranks hold the same dense weights; TP does not, because TP ranks hold different halves.
  • EP group (sparse view, axis ep): token all-to-all to the GPUs that own each token's experts. It contains whole TP and CP groups, so it is tp × cp × part of dp_shard.
  • Expert FSDP group (axis edp_shard = dp_shard · cp · tp / ep): all-gather / reduce-scatter of expert weights among ranks that own the same experts.
